# origami-panes

ペイン(分割/タブ/ドロワー)のツリー状態・レイアウト計算・ドラッグ&
ドロップ判定を持つ、UIフレームワーク非依存の純粋なRustロジック。
`serde`/`serde_json`以外の依存を持たない。

`origami`(Qt/QML)側のペインシステム(`qml/pane/{core,groups}`)の
移植として`origami-slint`の中で書かれたが、実際にはSlintにも一切
依存していなかったため、QML実装の廃止予定に合わせて`origami-kit`側に
切り出した。バックエンドが1つになる以上、これは「Slint専用」ではなく
フレームワークの中核ロジックという位置づけ。

## 提供するもの

- `pane_tree`: `PaneNode`(Split/Tabs/Drawer/Pane)のツリーデータ模型と、
  タブの追加/削除/移動、分割、ドロワーの折り畳みなどのミューテーション。
- `layout`: ツリーを実際の矩形群(`PaneRect`のフラットなリスト)に変換する
  計算。再帰的なコンポーネントネストではなくフラットなセルリストを選んだ
  理由は同モジュールのdocコメントを参照。
- `drop`: ドラッグ中のドロップ先判定(タブストリップへの挿入、リーフの
  上下左右への分割挿入など)。

## 使う側の責務

- 実際の描画(Slintの`.slint`コンポーネント、Qt Quickの`.qml`など)は
  このクレートの外。`origami-slint`の`ui/pane_host.slint`がSlint向けの
  実装例。
- `PaneTree`のシリアライズ(`serialize_json`/`from_json`)はこのクレートが
  提供するが、ワークスペースの保存パス自体は利用側アプリの責務。
- 既知の未対応: 空になった`Tabs`/`Drawer`グループはツリーから自動で
  刈り取られない(全タブを閉じても空グループのノードが残る)。利用側で
  操作後に刈り取るヘルパーを書くか、ここに刈り取りロジックを足すかは
  未決定。
